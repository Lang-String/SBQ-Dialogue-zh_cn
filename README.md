# SBQ-Dialogue translation for Chinese SBQ模组文本中文翻译
一个围绕Starbecue模组准备的用于对话公开参与征集或文本翻译的存储库

下载该存储库并将其移动到Starbecue所在的mods文件夹中，存储库会对Starbecue中的文本进行覆盖/添加。Starbecue在之前更新后是元数据中的版本，只要文本内容没有主要更新，模组本体与文本应该会在未来的版本中互相兼容。

如果用于翻译，将为每种语言单独创建一个分支。

所有 `.config` `.dialogue` 和 `.dialogueTree` 文件都应使用UTF-8 JSONC格式读取，虽然但是，SBQ引擎允许星界边境的Json解析尾随逗号。

不要更改keys<尖括号及其中的内容>，否则将无法运行！只更改值！

如果文件中缺少值，大部分SBQ文本字符串将在打印它们的键时用前面的冒号`:`来代替它们的值。

## GUI文本
大部分玩家看到的GUI文本存储在单个文件`sbqStrings.config`中

## NPC对话文本
基础NPC对话位于`npcs/sbq/dialogue/default.dialogue`，其他性格变量在同一文件夹中。

原创角色(OC)NPC对话路径位于`npcs/sbq/(所有者)/(OC名称)/npc.dialogue`

除非您要给未使用/未实现的对话触发器添加对话，否则您不需要为相关的对话修改`.dialogueTree`文件！对话树文件中不应含有直接向玩家显示的文本，如果有，应将文本移动到对话文件中，并修改对话树中的条目为从对话文件中引用文本。

在进行任何对话更改后，建议至少在推送提交之前运行对话验证脚本。(如果您不知道如何操作，别急)

# 脚本
我在大量的工作进展中使用了共计三个实用脚本，主要用于排序或验证工作是否正确。

### 依赖项
- https://nodejs.org/en/download
- https://www.npmjs.com/package/comment-json

## 排序对话
`node sortDialogue.js  (path to .dialogueTree)  (path to .dialogue)  (opt base .dialogue file)`

用于读取对话树和配对的对话文件，根据其在对话树中的使用位置对其内容进行排序，记录对话树引用缺失的对话片段的任何实例，并将未使用的对话片段放在对话文件的底部。

可以为第三个可选参数提供一个辅助基本对话文件，用于引用并指向缺失的行，而不是简单地指出它们缺失。在处理个性变体对话时最有用，并且只需将默认值用作缺失行的基础。

## 验证对话
`node  verifyDialogue.js`

用于验证所有对话是否有效，不包含循环引用循环，并且相同对话行的重复实例是对第一个唯一实例的引用。如果有任何对缺失的对话片段进行了引用，将进行记录。

该脚本预先加载了要检查和验证的对话文件列表，如果添加了更多对话，只需将其添加到其中的列表中。

## 取消引用对话
`node  unReferenceDialogue.js`

只是遍历其对话文件列表，并将文件中或其他文件中用于引用对话的路径替换为所引用的文本组。

我仅用这个来使编写独立角色的特殊对话更容易，同时仍然能够将基本对话作为示例，我建议在随后都重新运行一遍验证脚本。
